# Лабораторная 2. Тестирование open-source проекта

Автор: Скляров Константин Александрович, группа РИМ-150975к.

Проект: https://github.com/un33k/python-slugify, библиотека транслитерации и создания URL-slug.
Исходный commit: 866401ea6b346d7575cf941bc73ad32a362e34aa. Python 3.12.14, Windows, pytest 9.1.1, pytest-cov 7.1.0.
Изучены README.md, pyproject.toml, dev.requirements.txt и AGENTS.md. Ветка upstream — master.
Legacy-код и существующие тесты не изменялись; добавлены два отдельных файла тестов.

До: 126 прошедших тестов, покрытие строк 98,7879%, совместная метрика строк/ветвей 98,1328%.
После: 131 прошедший тест, совместная метрика строк/ветвей 99.3776%.
Точные значения и пропущенные строки находятся в evidence/slugify-before.json и slugify-after.json.
Покрытие frozen legacy выросло за счёт проверки ошибочного ввода и выбора backend.
Для subprocess-тестов на Windows включён PYTHONUTF8=1: без него исходный тест stdin
не проходит при кодировке cp1251. Исходные тесты не менялись.

Добавлены 5 тестов: CLI с sys.argv, KeyboardInterrupt с кодом -1 и без traceback,
TypeError при неверном типе текста, распространение ModuleNotFoundError вложенной зависимости,
явное указание text-unidecode без fallback. Mock изолирует импорт backend без установки
дополнительного backend и не подменяет функцию slugify.

Для сдачи создать fork проекта, перенести два файла в tests/ на отдельной ветке,
запустить полный pytest и открыть PR в un33k/python-slugify:master.
Отчёт с фактической ссылкой на PR положить в Practice102/СкляровКА/СкляровКА.md.
Pull request в исходный проект: https://github.com/un33k/python-slugify/pull/203. Тесты и замеры выполнены локально.
